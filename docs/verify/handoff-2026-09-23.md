## 4. 剩余任务

### 4.1 D7：6 个 provider 统一 Runtime 合同（最大的一件）

方案 §8-D7。现状：接口与能力声明都有，但 `memory`/`cache`/`resource` 仍走内存实现、没有统一持久化后端
（见 `daemon/internal/runtime/backend.go` 的文件头注释）。涉及的 provider：
codex / pi / zcode / dsh / openai_compat / echo。

**建议单独一轮**，别和其它事混做。

### 4.2 D8：数据目录迁移（**不可逆，必须先问用户**）

`%USERPROFILE%\.pocketagentd\` → `%LOCALAPPDATA%\PocketAgent\data\`。
方案 §8-D8 要求：检测旧目录 → 复制到临时目录 → 校验 → fsync → atomic rename → migration marker，
失败保留旧目录、支持回滚。**没有用户明确点头不要动。**

### 4.3 真机 fixture 抓取（需要真机）

`docs/verify/testdata/output-contract/README.md` 里写明了缺口：现有 7 类场景用的是**按协议形状构造**的
样本，不是真机抓的。尤其**场景 4（上下文压缩边界）与场景 5（turn/completed 结构变化）**需要实际触发后
把真实 rollout 片段补进去（连同 daemon 版本、codex 版本、触发步骤、脱敏后的原始行）。

### 4.4 WatchEvents 加速通道（本轮新发现）

Android 端**从未实现过 `WatchEvents` 客户端**（实测 `grep watchEvents` 零命中），而 daemon 侧有该 RPC
（`daemon/internal/server/event_sequence.go` 的 `hostWatchers`）。
方案 §9.3 的"收到终局事件后不等待下一次轮询"目前**只部分满足**（最坏 3 秒）——要做到"立即"就得订阅它。
从零加一条长连接（鉴权/重连/生命周期）值得单独一轮。

### 4.5 README / AUDIT 同步（收尾活儿）

方案 §11 要求。现在 `README.md:37` 附近记的仍是旧 HEAD、旧工作树状态、旧进度。

**建议等 D7/D8 定了再做**，否则做完又要再同步一次。

## 5. 这个项目的规矩（踩过才知道）

1. **先写红灯测试再实现**；写完必须**反证**——把修复摘掉，确认测试真的会红。
   本轮每个提交都做了反证，反证输出写在提交信息里。编译失败不算真 RED。
2. **临时探针（`console.log`/`TEMP-RED-PROBE`/`debugger`）收尾必须清**，并用 `grep` 证明清干净了。
3. **交付报告只报本轮工具输出里有的数字**——没跑就说没跑，跑一半就说哪条没跑完。
4. **声称"某功能不存在"前先穷尽查证**（本轮的教训反了：多次发现"方案说缺、其实已有"，
   例如 `CollabScreen.kt` 是成品页、`pruneStalePrefs` 已存在只是要等 7 天）。
5. **注释写"为什么"不写"做了什么"**——这个仓库的中文注释风格是解释取舍。
6. 提交信息里**如实标注未做项与覆盖缺口**（例如某处无单测的理由）。
