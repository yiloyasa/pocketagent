# codex 接入完成清单（收口报告）

> 2026-09-17 · PocketAgent · 覆盖 daemon 与 Android 两侧

## 结论

**codex agent 的全面接入已收口**：daemon 侧完成协议全量接入（通知 / 反向请求 / 客户端方法三档覆盖），Android 侧完成只读面、通知、审批卡、设置页与**会话组织（分组 / 分叉 / 回滚）** 的全部调用点。真机端到端验证 **22/22 通过**，Android JVM 单测 **75 例全绿**，daemon `go test ./internal/...` 全绿。

## 一、协议覆盖（`tools/codex_coverage.py` 对着 codex-schema 实测）

| 层 | 精确实现 | 含动态/泛化 | 总数 |
|---|---|---|---|
| 通知（server → client） | 43 | 47 | 75 |
| 反向请求（client 被调用） | **10** | 10 | **10** |
| 客户端方法（client → server） | 28 | 48 | 95 |

- 反向请求 **10/10 全接**：审批四类（`shell` / `file_change` / `apply_patch` / `permissions`）+ 反问类（`request_user_input` / `mcp_elicitation`）走审批卡；无能力的请求（token 刷新等）按协议回 JSON-RPC error，**不伪造 decision**。
- 未精确实现的客户端方法属 codex 深度特性（外部编辑器协同、云任务等），daemon 返回明确错误而非静默吞掉。

## 二、daemon 侧能力

- 会话组织 7 个 RPC：`threadSection` list/create/delete/rename、`moveThreadToSection`、`fork`、`rollback`（分组的**事实源在 codex**，本地不存副本）。
- goal 下发：`thread/goal/set|clear`，线程未加载时暂存、`Run()` 拿到 codexTID 后补发。
- 审批卡片携带真实动作类型与文件列表（`item/fileChange/patchUpdated` 累积）。
- 本轮修复的三处缺陷：
  1. **分叉后时间线空白**：`forkSeedMessages` 优先读新线程自己的 rollout 回填历史，读不到再退回复制源会话（真复制切片）；
  2. **分叉标题被 codex 同步覆盖**：建完即 `SetCodexThreadName` 推回「· 分支」标题；
  3. **rollback 日志计数恒为 0**：循环减掉请求计数后才打日志，先存 `asked` 再输出。

## 三、Android 侧 UI

- 会话列表筛选 chip 行：全部 / 已归档 / 未分组 / 各分组（带会话计数徽标）；「新建分组」固定钉在行右端，分组多时入口永不丢失。
- 长按分组 chip → 管理（改名预填当前名 / 删除带后果说明「组里的会话不会被删除，只会变成未分组」）；长按会话卡 → 移入分组 / 新建并移入 / 分叉。
- 聊天页「更多」面板：分叉会话（说明「原会话保持不变」）、回滚（列可选回合档位，后果文案明确「不会撤销文件改动、历史找不回来」，确认按钮红色）。
- 新增纯逻辑模块 `ui/ThreadOrganize.kt` + `ThreadOrganizeTest`（筛选哨兵、回滚档位、后果文案钉住）。
