# PocketAgent UI、工作区与交互改进方案

**日期：** 2026-09-15  
**状态：** 方案已记录，等待实现  
**范围：** Android 客户端、daemon 工作区语义、终端会话、附件上传、会话状态展示、侧边栏、设置反馈和启动动画

## 1. 目标与总体结论

本轮不新增云端能力，不改变 Agent 的核心协议方向，优先修复当前影响日常使用的三个根因：

1. **目录上下文没有统一**：终端、文件、Git、附件分别落到了 daemon 默认目录或固定目录，没有稳定跟随当前会话的 workspace。
2. **状态与详情没有分层**：工具状态、MCP 状态、线程状态和用量卡片全部直接堆在聊天时间线上，导致会话拥挤，且错误不易定位。
3. **界面反馈和动效不完整**：设置项点击后缺少即时反馈，侧边栏尺寸不完整，点击和页面切换缺少连续、可打断的过渡。

实现时采用“**全局电脑浏览**”与“**会话工作区执行**”两种明确语义：

- 侧边栏的“文件”入口：默认浏览整台电脑，从盘符/根目录开始。
- 当前会话中的终端、附件、Git 和 Agent 文件操作：始终使用该会话的 workspace。
- 未选择会话 workspace 时，允许用户显式选择，不再静默回退到 `C:\dev`。

## 2. 现状问题与验收标准

### 2.1 终端工作目录和切换目录

**问题：**

- 终端界面标题显示了 `G:\试验区`，但实际 PowerShell prompt 仍为：

  ```text
  PS C:\dev\pocketagent\daemon>
  ```

- 切换目录后出现 `UNKNOWN: EOF`，说明终端流或 PTY 生命周期在切换时被提前关闭，且新目录没有稳定建立新的终端会话。

**方案：**

- daemon 创建 PTY 时接收明确的 `cwd`，不再使用进程默认目录。
- `cwd` 统一从当前会话 workspace 或用户在终端中选择的目录产生。
- 终端切换目录时采用“停止旧会话 → 等待关闭完成 → 创建新 PTY → 回传 ready 状态”的顺序。
- 为每个终端会话分配 `terminalSessionId` 和 `cwd`，避免旧流的 EOF 误报到新会话。
- Android 端在切换期间显示“正在切换目录”，成功后显示真实 cwd；只有旧会话异常关闭且新会话未建立时显示错误。
- `UNKNOWN: EOF` 转换为可理解的中文错误，例如“旧终端已关闭，正在重新连接”，不能作为最终状态保留。

**验收：**

- 选择 `G:\试验区` 后，prompt 必须显示 `PS G:\试验区>`。
- 在终端中执行 `Get-Location`，结果与标题目录一致。
- 切换到另一个目录后，prompt、文件列表和后续命令都使用新目录。
- 连续切换两次不会出现旧终端输出污染新终端。
- 切换失败时保留原终端或提供“重试”，不会留下空白终端。

### 2.2 工具详情全局开关与审批弹窗

**问题：**

- 工具详情直接堆在会话中，默认信息量过大。
- 审批弹窗的默认折叠行为需要保留，但右上角缺少明确的展开控制。
- MCP 错误信息过长，直接破坏聊天节奏。

**方案：**

- 在全局设置增加“工具详情”选项：

  ```text
  工具详情
  ○ 折叠（默认）
  ○ 展开
  ```

- 设置只控制普通会话中的工具卡片；审批弹窗始终默认折叠，不被全局展开设置覆盖。
- 普通会话折叠态只显示：
  - 工具名称；
  - 成功/失败/运行中状态；
  - 必要的短摘要。
- 展开态再显示参数、输出、耗时和错误详情。
- 审批弹窗右上角增加展开/折叠按钮：
  - 默认折叠；
  - 展开显示命令、参数和工作目录；
  - 关闭弹窗或进入下一条审批时恢复默认折叠。
- 错误内容使用可折叠的错误区域，首行显示简短原因，完整错误放在详情中。

**验收：**

- 首次安装和清除设置后，普通工具卡片默认折叠。
- 修改全局设置为“展开”后，新出现的普通工具卡片默认展开。
- 审批弹窗无论全局设置为何，首次打开都默认折叠。
- 审批弹窗右上角按钮可以展开和收回详细命令。
- `program not found` 等错误不再以多张大卡片连续撑满聊天窗口。

### 2.3 会话窗口信息密度与状态表达

**问题：**

- MCP、线程、用量等所有细节都放在聊天正文中。
- 用户真正关心的是任务是否正常、是否失败、是否正在恢复。
- 上下文窗口信息的位置不符合阅读顺序。

**方案：**

- 会话正文只保留用户消息、Agent 消息、必要的工具摘要和审批卡片。
- 工具/MCP/线程等后台状态统一压缩为顶部状态区或单个状态入口。
- 每条会话标题右侧只显示一个状态点：
  - 蓝色：运行中/正在处理；
  - 绿色：本轮成功完成；
  - 红色：失败；
  - 灰色：未连接/已停止。
- 失败时自动进入有限次数重连：
  - 首次失败立即显示红点和“正在重连”；
  - 重连成功恢复蓝点或绿点；
  - 达到上限后保留红点，并提供手动重试。
- 上下文窗口显示移动到对话栏模型选择区域的左侧，例如：

  ```text
  上下文 32k   ·   Echo（内置）
  ```

- 用量限制卡片不再重复插入会话正文；改为可点击的顶部摘要或模型栏入口。

**验收：**

- 正常会话中不再连续出现 MCP 状态大卡片。
- 用户发送成功后，右上角只出现蓝色状态点，不新增大块状态文本。
- 任务失败时显示红点并自动重连。
- 上下文信息位于模型名称左侧，横竖屏和较长模型名下不溢出。

### 2.4 侧边栏和 Git 面板尺寸

**问题：**

- 侧边栏没有填满可用高度或宽度。
- Git 侧边栏右侧/底部留出异常空白，弹层与系统安全区域的关系不稳定。

**方案：**

- 侧边栏使用完整窗口可用尺寸，外层处理系统栏 inset，内层不重复计算。
- 侧边栏内容采用 `fillMaxHeight()`，底部区域使用 `weight(1f)` 吸收剩余空间。
- Git 面板复用同一套 sheet/drawer 容器和圆角规范，不单独写固定高度。
- 统一处理：
  - 状态栏 padding；
  - 导航栏 padding；
  - 键盘 padding；
  - 右侧/左侧抽屉宽度。
- 横向边距使用设计 token，不使用会导致不同设备空白失衡的固定屏幕比例。

**验收：**

- 侧边栏从状态栏下方延伸到底部安全区域。
- Git 面板在不同屏幕高度下填满可用区域。
- 打开和关闭侧边栏时没有白边、灰边或内容穿透。
- 旋转屏幕或切换系统字体大小后不发生明显裁切。

### 2.5 附件上传到当前会话 workspace

**问题：**

- 附件仍然上传到固定的 `C:\dev` 或 daemon 默认目录。
- 当前会话所属的 workspace 没有成为上传目标。

**方案：**

- 上传前先读取当前 thread 的 workspace。
- 目标路径固定为：

  ```text
  <thread.workspace>\.pocketagent-uploads\<unique-file-name>
  ```

- 文件名使用时间戳、随机后缀或内容 ID，避免同名覆盖。
- thread 没有 workspace 时：
  - 不再静默使用 `C:\dev`；
  - 显示“请先选择工作区”；
  - 或由用户确认一次默认目录。
- daemon 服务端再次校验目标路径必须位于 thread workspace 内。
- 聊天消息中显示相对路径或文件名，完整绝对路径只放在详情中。

**验收：**

- 会话 workspace 为 `G:\项目1` 时，附件落在：

  ```text
  G:\项目1\.pocketagent-uploads\
  ```

- 更换会话后上传目标跟随新会话 workspace。
- 无 workspace 时不会写入 `C:\dev`。
- Agent 能通过消息中的附件引用读取该文件。

### 2.6 设置界面点击无反馈

**问题：**

- 设置项点击后没有可见状态。
- 用户不知道切换是否成功、是否已经保存。

**方案：**

- 所有设置项采用明确的状态模型：

  ```text
  idle → changing → saved / failed
  ```

- 布尔开关在按下时立即更新视觉状态，保存失败时回滚并显示错误。
- 选择项显示当前值，而不是只显示一个无状态的按钮。
- 需要重启或重新连接的设置显示“将在下次连接生效”。
- 保存成功提供轻量反馈：
  - 行内勾选；
  - Snackbar；
  - 或底部短暂状态文字。
- 失败反馈包含具体原因和重试操作。

**验收：**

- 点击每个设置项后，200ms 内出现按下或切换反馈。
- 成功保存后能看到明确的已保存状态。
- 保存失败时不显示成功状态。
- 返回设置页再进入，显示的值与实际配置一致。

### 2.7 全局点击和页面交互动效

**问题：**

- 当前点击、抽屉、弹窗和页面切换偏硬，缺少连续性。

**方案：**

- 普通点击反馈在 pointer down/按下阶段出现，不等待页面切换完成。
- 页面切换、抽屉和审批弹窗采用可打断的 spring/低幅度过渡：
  - 主要页面：快速、无明显回弹；
  - 侧边栏：有轻微跟手效果；
  - 审批弹窗：平滑出现，不允许拖拽关闭。
- 不为每个小控件添加独立动画，避免过度运动。
- 统一动画 token：

  ```text
  pressScale: 0.97
  standardResponse: 0.30–0.40s
  sheetResponse: 0.30s
  defaultDamping: 1.0
  ```

- 支持 `prefers-reduced-motion`/Android reduced motion，关闭位移和回弹，只保留淡入淡出。

**验收：**

- 点击按钮有即时按压反馈。
- 侧边栏打开、关闭可连续反向，不出现跳变。
- 动画过程中再次点击不会等待上一段动画结束。
- 开启减少动态效果后，页面仍然可用且不产生明显位移。

### 2.8 文件入口默认浏览整台电脑

**问题：**

- 从侧边栏进入“文件”时，默认显示 `C:\dev`，而不是整台电脑。

**方案：**

- 将“文件入口”的根节点与“会话 workspace”完全分离。
- 全局文件浏览器初始显示 Windows 计算机根层：

  ```text
  此电脑
  ├── C:\
  ├── D:\
  ├── E:\
  └── 其他可访问盘符
  ```

- Windows 根层由 daemon 提供盘符列表；Android 不直接读取电脑文件系统。
- 进入文件夹后，使用相对路径导航。
- 当前会话 workspace 只作为文件入口中的一个快捷入口，不作为默认根目录。

**验收：**

- 点击侧边栏“文件”后首屏显示盘符/此电脑。
- 不会自动进入 `C:\dev`。
- 点击 workspace 快捷入口后才进入会话目录。
- 无权限的盘符显示不可访问原因，而不是空白页面。

### 2.9 左上角品牌图标安全空间

**问题：**

- 左上角 PA 图标与右侧 `PocketAgent` 文字距离过近，视觉上粘连。

**方案：**

- 将品牌区视为独立组件，不让图标和文字共享紧缩布局。
- 图标和文字之间使用明确的 horizontal spacing。
- 品牌区整体保留触控安全边距，避免贴近系统状态栏和侧边栏按钮。
- 图标、品牌名和副标题分别定义 baseline，避免垂直方向看起来拥挤。

**验收：**

- 图标与 `PocketAgent` 之间有稳定可见的安全间距。
- 大字体、横屏和不同语言下不发生重叠。
- 品牌区与菜单/关闭按钮之间有独立留白。

### 2.10 启动动画优化

**参考素材：**

```text
C:\Users\yanzi\WorkBuddy\优化\Pocket_agent_启动动效_优化版.mp4
```

该视频为 1080×2400、60fps、约 4.3 秒。可见方向是白底、品牌文字居中、`PocketAgent` 黑蓝双色字标和柔和蓝色光晕/扫描效果。

**方案：**

- 启动动画分为三个阶段：

  1. **品牌出现**：PA/品牌字标淡入并轻微缩放；
  2. **能量扫描**：蓝色高光沿 `agent` 区域通过，光晕只作为辅助，不覆盖字形；
  3. **进入主页**：品牌保持稳定后淡出，主页从当前视觉状态连续接管。

- 启动页与主页使用同一套品牌资源，避免启动页和主界面出现两个不同的 Logo。
- 不使用固定延迟强行阻塞启动；如果连接或数据恢复还未完成，动画结束后进入加载态。
- 允许动画被启动完成状态提前截断，避免网络快时等待 4.3 秒。
- 动画使用可取消、可重复进入的状态机，不在 Activity 中堆叠多个 `LaunchedEffect`。

**验收：**

- 冷启动时动画不会闪白、跳黑或出现 Logo 位移。
- 快速启动时不会人为等待完整视频时长。
- 主页接管时 Logo 的位置、大小和颜色连续。
- 关闭系统动画后使用淡入淡出替代扫描和缩放。

## 3. 代码实施分层

### daemon

重点检查和修改：

```text
daemon/internal/term/manager.go
daemon/internal/server/terminal.go
daemon/internal/server/fs.go
daemon/internal/server/thread.go
daemon/internal/store/store.go
proto/v1/terminal.proto
proto/v1/thread.proto
proto/v1/fs.proto
```

主要职责：

- 接收并验证 workspace/cwd；
- 创建和重建 PTY；
- 返回计算机根目录和盘符；
- 校验附件目标路径；
- 为 thread 保存 workspace；
- 区分旧终端 EOF 与当前终端错误。

### Android

重点检查和修改：

```text
android/app/src/main/java/dev/pocketagent/app/ui/TerminalScreen.kt
android/app/src/main/java/dev/pocketagent/app/ui/ChatScreen.kt
android/app/src/main/java/dev/pocketagent/app/ui/TurnSession.kt
android/app/src/main/java/dev/pocketagent/app/ui/AppDrawer.kt
android/app/src/main/java/dev/pocketagent/app/ui/FilesScreen.kt
android/app/src/main/java/dev/pocketagent/app/ui/GitScreen.kt
android/app/src/main/java/dev/pocketagent/app/ui/SettingsScreen.kt
android/app/src/main/java/dev/pocketagent/app/ui/Splash.kt
android/app/src/main/java/dev/pocketagent/app/ui/anim/PaAnim.kt
android/app/src/main/java/dev/pocketagent/app/AgentConnection.kt
```

主要职责：

- 保存当前 thread workspace；
- 终端切换时传递 cwd 并处理状态；
- 附件上传跟随 thread workspace；
- 普通工具详情设置；
- 审批弹窗独立折叠状态；
- 会话顶部状态点；
- 文件入口从 computer root 开始；
- 设置项保存反馈；
- 抽屉/Git 面板布局；
- 品牌间距和启动动画。

## 4. 推荐实现顺序

### 阶段 A：先修复功能正确性

1. thread workspace 数据流；
2. 终端 cwd 和切换；
3. 附件上传路径；
4. 文件根目录；
5. Git/侧边栏尺寸；
6. 失败自动重连状态。

### 阶段 B：再修复信息架构

1. 工具详情全局开关；
2. 审批弹窗展开按钮；
3. 会话详情压缩；
4. 状态点；
5. 上下文窗口位置；
6. 设置项成功/失败反馈。

### 阶段 C：最后统一动效和品牌

1. 点击反馈；
2. 抽屉和弹窗过渡；
3. 页面切换；
4. 左上角品牌间距；
5. 启动动画状态机。
