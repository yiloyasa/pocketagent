# 从零理解这个项目(写给第一次接触的你)

## 1. 整个系统在干什么

想象你在公司,家里电脑上有个项目跑挂了。你掏出手机:

```
手机 app ──( WiFi/4G )──► 家里电脑上的 daemon ──► 大模型 API
   │                          │
   │  "看看日志,告诉我哪错了"     │ 读你项目的文件
   │                          │ 跑个命令试试
   │ ◄── 逐字回复 + "我要跑 rm 命令,允许吗?"
   │      "允许" ──►           │ 真的执行
   │ ◄── "修好了,已提交 commit"
```

**手机只是遥控器**(显示和输入),**daemon 是干活的**(读文件、跑命令、改代码),
**大模型是大脑**(决定下一步干什么)。

## 2. 三个关键概念

### gRPC(手机和 daemon 说话的语言)
gRPC = 定义一份"菜单"(proto 文件:有哪些服务、每个服务有哪些方法、参数是什么),
然后手机和 daemon 各自用工具生成代码,调用就像本地函数一样。
菜单在 `proto/v1/*.proto`,这是**整个项目唯一的契约**,两边都必须遵守。

### 双向流(two-way streaming)
普通请求像点外卖:发一次,收一次。双向流像打电话:两边可以随时说话。
聊天(StartTurn)和终端(Attach)都是双向流——所以你打一个字,电脑立刻回显;
agent 想到一个字,手机立刻显示。

### PTY(伪终端)
你在 xterm.js 里看到的"终端",其实是个渲染器。真正跑 PowerShell/bash 的是电脑上的
PTY。PTY 吐出的是原始字节流(包括"红色""光标左移"这类 ANSI 控制码),
xterm.js 负责翻译成像素。手机终端和电脑终端画面一致,因为字节流一致。

## 3. 代码导读(按阅读顺序)

| 文件 | 讲什么 |
|---|---|
| `proto/v1/thread.proto` | 先看这个:一次对话长什么样 |
| `daemon/internal/agent/provider.go` | Provider 接口:换模型不动其他代码 |
| `daemon/internal/agent/openai_compat.go` | agent 循环:调模型→用工具→再调模型… |
| `daemon/internal/server/thread.go` | StartTurn:双向流 + 审批中继 |
| `daemon/internal/term/manager.go` | PTY 会话管理 |
| `android/.../ui/ChatScreen.kt` | 手机端收流式事件上屏 |
| `android/.../ui/TerminalScreen.kt` | xterm.js ↔ gRPC 桥接 |

## 4. API key 是什么(比喻)

大模型 API 像"发电厂",你的 app 是"电器",API key 是"电卡"。
- 电卡去哪办:智谱 open.bigmodel.cn 或 DeepSeek platform.deepseek.com,注册即送
- 怎么用:`set GLM_API_KEY=xxx` 然后启动 daemon,它自动发现
- 花多少钱:按用量计费(输入+输出的 token 数),开发期免费额度绰绰有余;
  正常重度使用大约每天几毛到几块钱
- 不想花钱:家里电脑配置好(GPU)可以跑 Ollama 本地模型,零成本(P1 支持)
