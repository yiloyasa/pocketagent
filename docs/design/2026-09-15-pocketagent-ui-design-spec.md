# PocketAgent UI 设计规范

**版本** 1.0 · **日期** 2026-09-15 · **范围** 设置 / 首页 / 侧边导航 及任务中心
**设计对象** Android（Jetpack Compose，`ui/theme/Pa.kt` 令牌体系）

---

## 0. 文档说明

### 0.1 本轮设计范围

对手机端 App 的**设置页、首页、侧边导航栏**做界面重做，覆盖八个模块：

| # | 模块 | 核心目标 |
|---|---|---|
| 1 | 会话归档管理 | 列表侧滑完成删除与重命名，仅当前行露出操作，支持连续处理多条 |
| 2 | 对话交互 | 长按弹出锚点上下文菜单，明确指向被操作对象 |
| 3 | 加载与等待 | 连接期间用骨架屏预展示内容结构 |
| 4 | 文件与任务能力 | 产出物（文件 / 网站 / APK）可下载到手机查看；耗时任务转后台 |
| 5 | 后台任务与任务中心 | 退出会话后任务转后台，任务中心分「消息处理 / 文件下载」 |
| 6 | 上下文窗口展示 | 显示已用与剩余，并给出对话消息 / MCP技能 / 子Agent 的占用比例 |
| 7 | 任务中心消息提示 | 图标右上角数字角标，不使用弹窗 |
| 8 | 生成物撤销与删除 | 待操作提示附带可立即执行的按钮，操作后上方出现可撤销入口 |

### 0.2 设计约束（不可突破）

1. **界面简洁性** —— 任一屏幕常驻可见的交互元素 ≤ 3 组；次要动作一律收进侧滑 / 长按 / 展开。
2. **操作连贯性** —— 支持连续处理同类信息，中途不被弹窗打断；任何破坏性操作必有可逆入口。
3. **回退原则** —— 不新增 proto / RPC。本轮八个模块中，仅模块 4 的大文件下载需要扩 `ReadFileRequest.offset`，其余全部复用现有能力。
4. **模块 6 文案红线** —— 上下文窗口卡片内**不得出现任何解释性文字**，只允许呈现分段名称、数值与单位（k / M / %）。

### 0.3 设计原则

- **一致性优先于新颖**：新组件必须复用既有令牌（色 / 字 / 距 / 圆角 / 动效），不引入第二套视觉语言。
- **反馈即时**：任何破坏性动作立即生效 + 提供撤销，而非用确认弹窗阻塞流程。
- **状态可预期**：加载、空、错误、降级四种状态都必须有明确设计，不留白屏。
- **无障碍内建**：手势操作必须提供非手势替代路径（见 §4）。

## 1. 设计基础 Design Foundations

### 1.1 色彩系统

#### 基础色板（实测自 `ui/theme/PaTheme.kt`）

App 采用「海拔分层」模型：越浮在上层的表面越亮。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `Pa.Bg` | `#F6F6F8` | `#000000` | 页面底色 |
| `Pa.Card` | `#FFFFFF` | `#151517` | 一级卡片 |
| `Pa.CardHigh` | `#F0F0F3` | `#1F1F22` | 抽屉、二级内嵌面、浮层 |
| `Pa.Hover` | `#E4E4E9` | `#2A2A2E` | 按压高亮 / 进度条空槽 |
| `Pa.Separator` | `#E6E6EB` | `#26262A` | 分隔线（1dp） |

#### 文字色

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `Pa.TextPrimary` | `#17171A` | `#F2F2F4` | 标题、主要数值 |
| `Pa.TextSecondary` | `#6A6A72` | `#98989F` | 正文、次级信息 |
| `Pa.TextTertiary` | `#9E9EA6` | `#5A5A60` | 辅助说明、占位 |

#### 语义色

| 令牌 | 浅色 | 深色 | 语义 |
|---|---|---|---|
| `Pa.Accent` | `#2F7FE8` | `#4A9DFF` | 品牌蓝、选中态、运行中 |
| `Pa.AccentDim` | `#D9E9FF` | `#1E3A5C` | 用户气泡底、蓝色弱底 |
| `Pa.Green` | `#1FA843` | `#32D74B` | 成功、充足、正常 |
| `Pa.Yellow` | `#C79400` | `#FFD60A` | 警告、偏紧 |
| `Pa.Red` | `#E5372B` | `#FF453A` | 错误、危险、不可逆 |

#### 数据可视化分段色（模块 6 专用）

| 分段 | 色值 | 说明 |
|---|---|---|
| 对话消息 | `Pa.Accent` | 复用品牌色 |
| MCP技能 | `#B584FF` | 沿用现有紫色，与品牌蓝区分度足够 |
| 子Agent | `Pa.Green` | — |
| 其他 | `Pa.TextTertiary` | 视觉后退，不抢主信息 |

> 分段色**固定不随剩余量变化**，保证可记忆。语义色仅用于「剩余量」量级表达。

#### ⚠️ 对比度审计（实测发现，需在实现阶段处理）

按 WCAG 2.1 相对亮度公式计算，浅色主题下小字号文本存在多处不达标：

| 组合 | 实测对比度 | AA 要求（正常文本 4.5:1） | 结论 |
|---|---|---|---|
| `TextPrimary` / `Card` | ≈ 16.5:1 | 4.5:1 | ✅ |
| `TextSecondary` / `Card` | ≈ 5.4:1 | 4.5:1 | ✅ |
| `Accent` / `Card` | ≈ 3.9:1 | 4.5:1 | ❌ 仅达大字号 3:1 |
| `Green` / `Card` | ≈ 3.1:1 | 4.5:1 | ❌ 仅达大字号 3:1 |
| `Red` / `Card` | ≈ 4.3:1 | 4.5:1 | ⚠️ 临界不达标 |
| **`TextTertiary` / `Card`** | **≈ 2.7:1** | 4.5:1 | ❌ **明显不达标，且被大量用于 10.5sp 说明文字** |

**处置建议（二选一，不改变色相）**

- **方案 A（推荐）**：保留令牌本色用于**图形元素**（图标、色块、进度条、边框，适用 3:1 非文本标准），另新增一套 `*Text` 变体专供小字号文本：
  `AccentText = #1F63C4`（≈5.4:1）、`GreenText = #177C33`（≈5.0:1）、`RedText = #C42B21`（≈5.2:1）、`TextTertiary → #767680`（≈4.6:1）
- **方案 B**：把说明类文字（现用 `TextTertiary` 10.5sp）统一提升为 `TextSecondary`。改动最小，但会削弱主次层级。

> 本规范中的尺寸与颜色规格均以方案 A 为基准标注；若选择方案 B，仅需替换文本着色令牌，布局不变。

### 1.2 字体系统

App 自带字体为 **Poppins**（`poppins_bold.ttf`），系统字体作为回退。

| 角色 | 字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|
| 页面主标题 | 17 sp | 500 | 1.3 | 抽屉品牌名、页面标题 |
| 区块标题 | 14.5 sp | 500 | 1.35 | 卡片标题、列表项主文案 |
| 区块标题（强调） | 14.5 sp | 600 | 1.35 | 选中态列表项 |
| 正文 | 13 sp | 400 | 1.5 | 消息正文、卡片内容 |
| 次要正文 | 12 sp | 400 | 1.45 | 数值标签、构成标题 |
| 辅助 / 标注 | 11 sp | 400 | 1.4 | 数值明细、角标、图例 |
| 微型标注 | 10.5 sp | 400 | 1.35 | 列表项描述（**须按 §1.1 审计结论调整色值**） |
| 主数值 | 15 sp | 500 | 1.2 | 「还剩 68%」等结论型数字 |

**规则**
- 字重仅用 400 / 500 / 600，不引入更多层级。
- 所有数值右对齐时使用等宽数字（Compose `FontFeatureSetting` 或手动对齐），避免百分比跳动。
- 同一卡片内字号层级不超过 3 档。

### 1.3 间距系统

基准单位 **4 dp**，实际使用阶梯：

| 令牌 | 值 | 用途 |
|---|---|---|
| `space-1` | 4 dp | 图标与文字间距、进度条与标签 |
| `space-2` | 8 dp | 行内元素间隔、角标偏移基准 |
| `space-3` | 10 dp | 组件内部小间隔（卡片内行距） |
| `space-4` | 12 dp | 按钮内边距、图例网格间距 |
| `space-5` | 14 dp | 块与块之间（卡片之间、区块之间） |
| `space-6` | 16 dp | 卡片内边距（水平）、页面左右边距 |
| `space-7` | 20 dp | 页面左右边距（抽屉内容区） |
| `space-8` | 26 dp | 面板级圆角配套留白 |

### 1.4 圆角与海拔

App 为**扁平设计**：不使用投影，靠色阶（Bg → Card → CardHigh → Hover）表达层级。

| 元素 | 圆角 | 说明 |
|---|---|---|
| 卡片 | 14 dp | 一级信息容器 |
| 面板 / 抽屉 | 26 dp（单侧） | 抽屉为 `topEnd/bottomEnd = 26 dp` |
| 按钮 / 输入框 | 12 dp | — |
| 列表项高亮 | 14 dp | — |
| 胶囊 / 进度条 | 50% | 全圆角 |
| 角标 | 50%（胶囊） | `minWidth 16 dp` |
| 分段色块 | 2 dp | 图例小方块 |
| 遮罩 | — | `Color.Black @ 55%`，不使用模糊 |

### 1.5 动效令牌

| 令牌 | 时长 | 缓动 | 用途 |
|---|---|---|---|
| `motion-instant` | 120 ms | `tween` | 菜单淡入、角标淡出 |
| `motion-fast` | 200 ms | `tween` | 抽屉遮罩、选中态、回弹 |
| `motion-normal` | 260 ms | `tween` | 抽屉滑入滑出 |
| `motion-spring` | ≈220 ms | `spring(dampingRatio 0.85, stiffness 500)` | 侧滑位移、可拖拽元素 |
| `motion-crossfade` | 300 ms | `tween` | 骨架屏 → 真实内容 |
| `motion-shimmer` | 1200 ms | `linear` 循环 | 骨架屏高光平移 |

**统一规则**
- 入场比出场略慢（如菜单 120 ms 进 / 100 ms 出），营造「响应迅速」的手感。
- 位移类动画一律走 `graphicsLayer`，不触发重组。
- **减弱动态效果**开启时：骨架屏取消平移、撤销条取消进度线动画、侧滑改为瞬时展开、抽屉取消滑入仅保留淡入。

## 2. 组件库 Component Library

本轮新增 8 个组件 + 1 处导航项改造。所有组件均须同时适配浅色 / 深色。

### 2.1 `SwipeRevealRow` 互斥侧滑容器

**用途** 在列表行上承载删除 / 重命名等操作，**同一时刻只允许一行处于展开态**。

**结构**
```
┌─────────────────────────────────────────────┐
│ [内容层：随手指水平位移]        │ 重命名 │ 删除 │
└─────────────────────────────────────────────┘
        ← 内容层 translationX = -offset
```

**尺寸规格**

| 项 | 值 |
|---|---|
| 单个动作宽度 | 76 dp |
| 最大动作数 | 2 |
| 动作图标 | 18 dp |
| 动作文字 | 11 sp / 400 |
| 圆角 | 内容层 14 dp（动作层随行高裁切） |
| 行最小高度 | 64 dp（满足 44 dp 触控目标 + 上下留白） |

**状态**

| 状态 | 表现 |
|---|---|
| 默认 | `offset = 0`，动作层被内容层完全遮挡 |
| 拖拽中 | 内容层跟手位移，不越界（`offset ∈ [-动作区宽, 0]`） |
| 越阈值 | 触发一次 `LongPress` 触感反馈 |
| 展开 | 内容层停在 `-动作区宽`，动作层完整可见 |
| 释放回弹 | `spring` 回 `0` 或 `-动作区宽`，约 220 ms |

**互斥规则** 列表外层持有一个 `openKey` 单值状态；任一行的 `openKey` 变为自己时，其他行以同一 spring 回弹至 `0`。

**关闭时机** ① 点动作按钮 ② 点该行内容 ③ 列表开始滚动 ④ 其他行被滑开 ⑤ 离开页面。

**手势判定（关键）** 使用 8 dp 方向阈值：垂直位移大于水平位移时**不拦截**事件，保证列表纵向滚动不受影响。

**无障碍**
- 每个动作必须能被 TalkBack 独立聚焦，并提供 `customActions` 映射「重命名 / 删除」——手势不能是唯一入口。
- 行内容层 `contentDescription` 不包含动作信息，避免重复播报。

### 2.2 `ContextMenu` 长按锚点菜单

**用途** 长按元素后在**按压点附近**展开操作，明确指向被操作对象。

**结构**
```
┌──────────────────────┐
│ 这条回复 · 前 12 字    │  ← 对象摘要行（必须存在）
├──────────────────────┤
│ 复制全文              │
│ 引用回复              │
│ 转发到新会话          │
│ 删除            (红)  │
└──────────────────────┘
```

**尺寸规格**

| 项 | 值 |
|---|---|
| 最小宽度 | 180 dp |
| 最大宽度 | 240 dp |
| 项高度 | 44 dp（满足触控目标） |
| 内边距 | 垂直 6 dp / 水平 14 dp |
| 圆角 | 14 dp |
| 底色 | `Pa.CardHigh`，0.5 dp `Pa.Separator` 描边 |
| 图标 | 16 dp，与文字间距 10 dp |
| 摘要行字号 | 11 sp / 400 / `Pa.TextTertiary` |
| 菜单项字号 | 13 sp / 400 / `Pa.TextPrimary` |
| 危险项 | 文字与图标 `Pa.Red` |

**定位规则** 优先展开于按压点**右下方**；水平越界则左翻，垂直越界则上翻；四周保留 12 dp 安全边。

**状态**

| 状态 | 表现 |
|---|---|
| 入场 | `fadeIn(120ms)` + `scaleIn(0.92 → 1.0)`，锚点为 `transformOrigin` |
| 对象指示 | 被长按元素在菜单展开期间保持 `Pa.Hover` 底色 |
| 按压预览 | 长按过程中该元素 `scale 1.02`（不使用阴影） |
| 出场 | 淡出 100 ms |

**菜单项随对象类型变化**

| 对象 | 菜单项 |
|---|---|
| 文本回复 | 复制全文 / 复制代码块 / 转发到新会话 / 引用回复 |
| 代码块 | 复制代码 / 保存为文件 / 在终端运行 |
| 图片、生成图 | 查看大图 / 保存到手机 / 重新生成 / 删除 |
| 工具调用卡 | 复制命令 / 复制输出 / 在终端重跑 |

**无障碍** 菜单容器标记为 `Modal` 语义；`BackHandler` 只关闭菜单，不退出页面。

### 2.3 `PaSkeleton` 骨架屏

**用途** 连接建立前预展示内容结构，避免白屏与居中转圈。

**规格**

| 项 | 值 |
|---|---|
| 底色 | `Pa.Card` |
| 高光 | `linearGradient`：`Pa.Hover → Pa.Card → Pa.Hover`，水平平移 1200 ms 循环 |
| 圆角 | 与对应真实元素一致 |
| 数量 | **按视口高度计算，不写死**（避免骨架 6 条、真实 2 条的跳变） |

**形状对位表**（必须与真实内容逐项对齐，否则切换时会跳动）

| 类型 | 结构 |
|---|---|
| `SESSION_ROW` | 圆形 38 dp + 两行文本条（宽 70% / 45%） |
| `MESSAGE_BUBBLE` | 左右交替、圆角 14 dp、行数随机 2–3 |
| `FILE_ROW` | 图标方块 32 dp + 单行文本条（宽 55%）+ 右侧尺寸条（宽 40 dp） |
| `CARD_BLOCK` | 卡片外形，内部两条文本条 |

**状态与降级**
- 连接超过 8000 ms 未就绪 → 骨架上方追加一行说明「网络较慢，正在重试」+ 当前通道名。
- 连接失败持续 15 s → 骨架整体替换为错误态 + 重试按钮，**不允许无限骨架**。
- 数据为空 → 骨架退场后显示空状态，不停留在骨架。
- 减弱动态效果 → 取消平移，改为静态 60% 透明度色块。

**无障碍** 骨架屏对 TalkBack 隐藏（`clearAndSetSemantics {}`），并播报一次「正在加载」。

### 2.4 `UndoBar` 可撤销提示条

**用途** 破坏性操作立即生效 + 顶部浮出可撤销入口。模块 1 / 5 / 8 共用。

**规格**

| 项 | 值 |
|---|---|
| 位置 | 页面**顶部**，顶部导航栏下方 8 dp（避开输入框与手势条） |
| 高度 | 44 dp |
| 圆角 | 14 dp |
| 底色 | `Pa.CardHigh`，0.5 dp `Pa.Separator` 描边 |
| 水平边距 | 16 dp |
| 文案 | 13 sp / 400 / `Pa.TextPrimary` |
| 操作按钮 | 「撤销」13 sp / 500 / `Pa.Accent`，右侧，触控区 ≥ 44 dp |
| 默认时长 | 5000 ms |
| 剩余指示 | 底部 2 dp 细线，随剩余时间收缩 |
| 错误态 | 底色转 `Pa.Red` 弱化版，文案「撤销失败，请重试」，不自动消失 |

**行为**
- 同时只存在一条；新操作**替换**旧条（符合连续处理预期）。
- 不拦截返回键与手势。
- 撤销采用**延迟真删（软删除）**：先本地移除，5 s 后才提交远端。即使断网也能撤销成功。

**无障碍** 出现时通过 `liveRegion = Polite` 播报；「撤销」按钮可聚焦。

### 2.5 `PaBadge` 数字角标

**用途** 在图标右上角显示未读数量。

**规格**

| 项 | 值 |
|---|---|
| 形态 | 胶囊，`minWidth 16 dp`，高 16 dp |
| 底色 | `Pa.Red` |
| 文字 | 10 sp / 500 / 白 |
| 描边 | 2 dp，浅色主题取 `Pa.Card`，深色主题取 `Pa.CardHigh` |
| 位置 | 相对图标 `Box` 右上，偏移 `x +2 dp, y -2 dp`，**不随选中态位移** |
| 溢出 | `count > 99` 显示 `99+` |
| 零值 | 完全不渲染（不显示灰色 0） |

**行为** 不使用弹窗、不打断当前操作；进入任务中心后延迟 500 ms 自动标为已读并 `fadeOut(200ms)`。

**无障碍** `contentDescription = "任务中心，N 条未处理"`。

### 2.6 `TaskCard` + `SegmentedTabs` 任务中心

**分类标签栏**

| 项 | 值 |
|---|---|
| 形态 | 分段控件，底槽 `Pa.CardHigh`，圆角 12 dp，高 36 dp |
| 选中项 | 底色 `Pa.Card`，文字 `Pa.TextPrimary` 500 |
| 未选中 | 文字 `Pa.TextSecondary` 400 |
| 计数 | 紧邻文案右侧，11 sp，`Pa.TextTertiary` |

**任务卡片**

| 项 | 值 |
|---|---|
| 圆角 | 14 dp |
| 内边距 | 14 dp |
| 标题 | 14.5 sp / 500 |
| 状态点 | 8 dp 圆形；运行中为 `Pa.Accent` 脉冲（`infiniteRepeatable` 缩放 1.0→1.3），完成 `Pa.Green`，失败 `Pa.Red` |
| 进度 | 线性条，高 4 dp，圆角 50% |
| 次要行 | 11 sp / `Pa.TextSecondary`，内容为耗时与来源通道 |
| 行动区 | 仅展开态显示：打开 / 重试 / 删除 |

**合并规则** 同一会话连续多轮合并为一条，显示「已完成 N 轮」，避免刷屏。

**无障碍** 状态点不能仅靠颜色区分，需附加文字（运行中 / 已完成 / 失败）。

### 2.7 `ArtifactCard` 产出物卡片

### 2.8 `ContextMeter` 上下文窗口卡（模块 6 改版）

**用途** 一屏内交代「还剩多少」与「已被谁占用」。**卡内不得出现任何解释性文字。**

**结构**

```
上下文空间                        剩余 68%
├───────────────●──────────────────────────┤     主条：已用(实心) / 剩余(空槽)
已用 41.2k            剩余 86.8k            上限 128k
────────────────────────────────────────────
构成                              41.2k
├───────────────┤───────┤────┤──┤              堆叠条：仅"已用"部分内部拆分
对话消息 58%   MCP技能 24%  子Agent 13%  其他 5%
```

**尺寸规格**

| 项 | 值 |
|---|---|
| 卡片圆角 / 内边距 | 14 dp / 14 dp |
| 标题 | 13 sp / 500 / `Pa.TextPrimary` |
| 剩余量 | 15 sp / 500，颜色随量级变化 |
| 主条高度 | 8 dp，圆角 50%，空槽 `Pa.Hover` |
| 数值行 | 11 sp / `Pa.TextSecondary`，三段式左中右对齐 |
| 分隔线 | 1 dp `Pa.Separator`，上下 12 dp |
| 「构成」标签 | 12 sp / `Pa.TextSecondary`，右侧总量 11 sp / `Pa.TextTertiary` |
| 堆叠条高度 | 8 dp，圆角 50%，段间无间隙 |
| 图例 | 2 列网格，列内间距 12 dp，行距 7 dp；色块 8 dp 圆角 2 dp；名称 11 sp `Pa.TextSecondary`；百分比 11 sp / 500 `Pa.TextPrimary` |

**量级语义**

| 剩余 | 主条色 | 剩余量文字色 |
|---|---|---|
| > 50% | `Pa.Green` | `Pa.TextPrimary` |
| 20 – 50% | `Pa.Accent` | `Pa.TextPrimary` |
| 10 – 20% | `Pa.Yellow` | `Pa.Yellow` |
| < 10% | `Pa.Red` | `Pa.Red`（数值行中的剩余值同步转红） |

**构成分段**

| 分段 | 色 | 取值口径 |
|---|---|---|
| 对话消息 | `Pa.Accent` | `role ∈ {user, assistant}` 的文本字符量 |
| MCP技能 | `#B584FF` | 工具名以 `mcp` 开头或含 `__`，并以已注册 MCP 服务器名兜底匹配 |
| 子Agent | `Pa.Green` | 工具名命中 `collab / spawn / subagent` |
| 其他 | `Pa.TextTertiary` | 思考、非 MCP 的普通工具调用、系统事件（保留此段使合计恒为 100%） |

**降级**
- `contextWindow == 0`（模型未上报上限）→ 隐藏主条与主百分比，**仅保留堆叠条与构成百分比**（构成不依赖窗口大小）。
- 会话为空 → 单项 `0%`，不出现空白条。

**文案红线（验收项）** 卡内允许出现的文字仅限：`上下文空间`、`剩余`、`已用`、`上限`、`构成`、四个分段名称、数值与单位 `k / M / %`。
任何说明性语句一律不得出现。

**无障碍** 主条与堆叠条均需提供文本等价语义（如 `剩余 68%，其中对话消息占 58%`），供 TalkBack 播报。

## 3. 界面设计（八个模块）

### 3.1 会话归档管理

**视觉结构** 会话列表行 = 标题（14.5 sp / 500，单行省略）+ 次要行（10.5 sp：时间 · 消息数）+ 右侧状态点（运行中 `Pa.Accent` / 归档 `Pa.TextTertiary`）。左滑后右侧露出「重命名」「删除」两个等宽动作。

**交互规格**
1. 左滑露出动作，**其余行保持原位**（互斥展开，见 §2.1）。
2. 点「重命名」→ 行内**原地**切换为 `OutlinedTextField`，自动聚焦并全选；`ImeAction.Done` 或点空白提交。全程不出现对话框。
3. 点「删除」→ 立即移除 + `UndoBar`「已删除「标题」· 撤销」，5 s 内可恢复且**列表顺序还原**。
4. 滑动中的行，其状态点与徽标随内容层一起位移，不脱层。

**状态**
| 状态 | 设计 |
|---|---|
| 空列表 | 空状态插画 + 「还没有会话」+ 新建入口 |
| 删除失败 | 行恢复原位 + `UndoBar` 转错误态 |
| 运行中会话被删除 | 动作区改显「停止并删除」（原地展开二次确认，非弹窗） |

**边界** 重命名空串视为取消、不发请求；超 80 字本地截断并提示；快速连续删除时 `UndoBar` 只保留最后一条。

---

### 3.2 对话交互

**视觉结构** 时间线由消息气泡、思考卡、工具调用卡、计划卡与产出物卡组成。长按任一元素触发锚点菜单（§2.2）。

**交互规格**
1. 长按 → 菜单出现在按压点附近，首行显示对象摘要，被操作元素保持 `Pa.Hover` 底色。
2. 菜单项按对象类型变化（见 §2.2 表格）。
3. 「转发到新会话」复用现有 `CreateThread`，将选中文本作为首条消息，不新增接口。

**状态与边界**
- 靠近屏幕边缘时菜单自动翻转，不得被裁切。
- 长列表滚动中长按 → 先停止滚动再弹出菜单。
- 内容为空时对应菜单项置灰不可点。
- 返回键只关闭菜单，不退出页面。

---

### 3.3 加载与等待

**设计目标** 让用户在等待期间就预知将出现的内容结构。

**规则**
1. 连接建立前（`connState != "ok"`）各页面显示对应类型的骨架屏，**不再使用居中转圈作为首屏主态**。
2. 数据到达后以 `Crossfade(300ms)` 过渡，不做整屏闪烁。
3. 增量加载时，已加载部分保持可见，末尾追加 2 条低透明度骨架。

**各页面骨架类型**

| 页面 | 类型 | 数量 |
|---|---|---|
| 首页「最近任务」 | `SESSION_ROW` | 按视口算 |
| 会话列表 | `SESSION_ROW` | 按视口算 |
| 聊天页历史 | `MESSAGE_BUBBLE` | 4 |
| 文件页 | `FILE_ROW` | 按视口算 |
| Git 页 | `CARD_BLOCK` | 3 |

**边界** 见 §2.3 的状态与降级。

---

### 3.4 文件与任务能力

**视觉结构** 助手回复中出现可下载产出时，气泡下方附 `ArtifactCard`（§2.7）。

**交互规格**
1. 卡片展示图标、文件名、大小、路径摘要与「下载」按钮；APK 额外带「应用」徽标，目录或网站标「打包下载」。
2. 下载中按钮变进度环，显示 `已下载 / 总大小`；可点「后台」将任务转入任务中心。
3. 完成后变为「已保存 · 打开」；APK 走系统安装器。

**技术约束（影响设计）**
`ReadFileRequest.max_bytes` 存在服务端默认上限（约 2 MB），**APK 与目录打包必然超出**。需扩 `ReadFileRequest.offset` 支持分块续传（仍是同一 RPC，向后兼容）。设计层面据此提供「断点续传」与「已下载部分保留」的界面表达。

**边界**
| 场景 | 设计 |
|---|---|
| 单文件 > 500 MB | 下载前二次确认 |
| 下载中断（切网 / 拔线） | 转入任务中心「文件下载」分类，显示「已暂停 · 继续」 |
| 磁盘不足 | 前置检查，给出明确提示，禁用下载按钮 |
| 源文件在电脑端已删除 | 卡片转灰并标注 |

---

### 3.5 后台任务与任务中心

**设计目标** 让「已转入后台」这件事可见、可回、可追踪。

**交互规格**
1. 退出会话时若有轮次在跑 → `UndoBar` 位置显示「任务已转入后台 · 查看」，同时角标 +1。
2. 侧边导航新增「任务中心」（§2.9）。
3. 任务中心顶部为分段标签「消息处理 / 文件下载」，各自显示计数。
4. 单条任务卡见 §2.6。
5. 点消息类任务卡 → 跳转对应会话；下载类 → 展开操作（打开 / 重试 / 删除）。
6. 右上角提供「全部标为已读」。

**关键前提** 运行时能力**已存在**：`TurnSession` 跑在 app 级作用域，`TurnKeepAliveService` 保活，退出聊天页不会中断。本模块是**可见性设计**，不是架构改造。

**边界**
| 场景 | 设计 |
|---|---|
| 同会话连续多轮 | 合并为一条，显示「已完成 N 轮」 |
| 完成时用户正在任务中心 | 该条不计未读 |
| daemon 断开导致失败 | 状态置为失败，提供「重试」 |
| App 被杀 | 重启后恢复未读计数；运行中任务标为「已中断」并给重试入口 |

---

### 3.6 上下文窗口展示

**设计目标** 从「密集」变为「一眼可读」，并给出占用构成。

**改版要点**
- 删除原 `UsageSection` 的**四维进度条**（输入 / 输出 / 缓存读 / 缓存写），这是"密集"的主因。
- 缓存读写不再单独展示，并入成本行（若保留成本信息）。
- 新增构成堆叠条与四段占比。
- **移除全部解释性文案**（原「这意味着什么」展开区作废）。

**完整规格** 见 §2.8。

**数据说明** 现有实现（`ChatScreen.kt` 的 `EstimateSection`）按 ≈4 字符/token 估算，源码注释自述「协议未提供逐项精确值」。协议侧 `McpServerStatus` 仅有 `name / tools / status`，无 token 字段，也无 skills / sub-agent 概念。故本设计的占比为**客户端估算值**，界面上不标注精度，但实现注释须说明来源。

**入口** 保持现状：点模型行左侧的上下文胶囊展开。会话列表与聊天页的显示须一致，不得因切换模型而消失。

---

### 3.7 任务中心消息提示（角标）

**设计目标** 用最小侵入的方式告知未读数量。

**规则**
- 角标只贴在侧边导航「任务中心」项的图标右上角（§2.5）。
- **不使用弹窗**、不使用 Toast、不打断当前操作。
- 进入任务中心后，可见的未读自动标为已读，角标淡出。
- 侧边栏关闭状态下角标也须保持更新。

**边界** 未读 > 99 显示 `99+`；未读为 0 完全不渲染；深浅主题下描边色自适应。

---

### 3.8 生成物撤销与删除

**设计目标** 破坏性操作通过「待操作提示 + 可立即执行的按钮」完成，执行后在上方保留可撤销入口。

**交互规格**
1. 长按生成物 → 锚点菜单出现「重新生成」「删除」（走 §2.2 的图片分支）。
2. 点「删除」→ **不弹确认框**，立即执行 + 顶部 `UndoBar`「已删除 1 张 · 撤销」。
3. `UndoBar` 上的「撤销」按钮可直接点击。
4. 撤销成功 → 文案换为「已恢复」，1.5 s 后自动消失。
5. 批量删除 → 文案为「已删除 N 项 · 撤销」，一次撤销全部。

**实现语义** 延迟真删（软删除）：先本地标记移除，5 s 后提交远端；撤销为纯本地操作，因此必然成功。若撤销窗口内离开页面，则立即提交。

**边界**
| 场景 | 设计 |
|---|---|
| 撤销窗口内 daemon 断开 | 撤销仍本地完成；提交阶段失败则 `UndoBar` 转错误态 |
| 连续删除多次 | 仅保留最后一次撤销机会 |
| 对象已在电脑端删除 | 提示「对象已不存在」 |

## 4. 无障碍规范

### 4.1 WCAG AA 要求

| 项 | 要求 |
|---|---|
| 文本对比度 | 正常文本 ≥ 4.5:1，大文本（≥18.66px 粗体 / ≥24px）≥ 3:1。**当前浅色主题多处不达标，见 §1.1 审计**。 |
| 非文本对比度 | 图标、边框、进度条等图形元素 ≥ 3:1 |
| 触控目标 | 交互元素 ≥ 44 × 44 dp |
| 键盘 / 手势替代 | 所有手势操作必须提供非手势替代路径 |
| 状态表达 | 不得仅用颜色区分状态，须辅以文字或形状 |
| 动效敏感 | 遵循系统「减弱动态效果」设置（§1.5） |

### 4.2 本轮的强制项

1. **侧滑动作必须有 `customActions`** —— TalkBack 用户无法执行滑动手势。
2. **角标必须有 `contentDescription`**。
3. **骨架屏必须对读屏隐藏**，避免播报无意义的占位内容。
4. **任务状态点必须附文字**（运行中 / 已完成 / 失败）。
5. **上下文窗口的两条进度条必须提供文本等价语义**。
6. **`UndoBar` 出现时须播报一次**（`liveRegion = Polite`）。
7. **锚点菜单须标记 Modal 语义**，并支持返回键关闭。
