# Pocket Agent 移动端界面优化稿

本目录交付的是**可交互设计原型与逐屏图片**，不是已经接入 Android 的功能。示例会话、任务、文件和主机名只用于说明界面。原型入口为 `prototype.html`；`screens/` 是同一组件和状态规则导出的逐屏 PNG。

## 产品边界与设计主线

手机负责发起、观察、回复与审批；电脑端 daemon 转发事件，实际工作由原生 Agent 执行。会话的运行状态、任务中心的进度和审批状态必须来自同一轮次/事件，不制造独立的“看似完成”状态。对等多 Agent 协同与父子委派分开表达；只有主机声明支持协同时才出现入口。配对要使用设备身份和验证码，证书指纹变化不能静默放行。连接中断时保留输入，重连只恢复事件，不重新发送上一条提示词。

这次把“要处理什么”置于“能做什么”之前：顶部统一主机状态，待审批优先于运行中，再到新建和历史。所有界面都用同一套主机胶囊、状态词、Agent 身份、操作按钮、导航返回层级；审批只在**独立弹窗**里决策，不在消息卡上放批准按钮。这个弹窗要求覆盖既有“尽量少弹层”的默认约定，因为用户明确指定审批形式。

## 视觉系统

- **重新设计**而不是给现有深色页换皮：以冷白画布 `#F6F7F6`、瓷白表面 `#FFFFFF`、石墨重点面 `#1E2835`、细线 `#E3E7EB` 和深墨正文 `#19222D` 建立编辑式层级。主色 `#386BE7` 只用于当前操作；绿色 `#21977D` 表示运行/已连接，琥珀色 `#A96726` 表示待用户处理，珊瑚红 `#C94F4D` 表示拒绝/未完成。语义不单靠颜色，必须同时写状态词。侧边栏与代码预览保留石墨深色，形成层次而非满屏深色卡片。
- 字体层级：页面标题 25/32，首页主标题 34/39，模块标题 16/22，正文 13–14/21，辅助 11–12/17；8px 网格，外边距 23px，主要点击区至少 44px。只有待处理、主机或协同这类有明确主次关系的内容进面板；普通任务、文件和会话使用留白与细分隔线，不套多层卡片。
- Agent 使用项目已有品牌图，未知 Agent 用中性占位而不是冒认品牌；图标统一细线风格，不使用 emoji。头像/身份只表示 Agent 或主机，不制造真人角色。所有图片里 Codex、Pi、DSH 的图标/名字一致。
- 页面骨架一致：状态栏 → 顶部导航（菜单或返回、标题、一个次操作）→ 主机状态 → 内容 → 底部输入/主操作。侧边栏是同层抽屉，不是新页面；审批弹窗是最上层。

## 状态与回退

状态口径统一为“等待你处理 / 正在执行 / 已完成 / 未完成”，并显示时间或来源；未连接时状态仍显示上次更新时间，不能写“正在执行”。按钮动作即时反馈，长请求显示处理中，失败时保留原上下文并给重试。连接候选并行尝试，成功后只展示实际采用的通道；证书不匹配则停在阻断状态，不自动降级。

系统返回/顶部返回遵循相同顺序：审批弹窗→关闭弹窗且**不作决定**；抽屉→关闭抽屉；二级详情→回来源页；筛选或搜索→先清当前临时状态；主页面→首页；首页→系统默认退出行为。切页先关抽屉再导航。对话上滑查看历史时停止自动滚底，显示“新内容”按钮；重连后回到同一会话位置。审批请求必须用 `thread_id + request_id` 对应当前请求；失效、重复、跨会话或提交失败时不显示已批准，不做乐观通过。弹窗外点击和返回等价于暂不处理，绝不等价于拒绝。

### 主流程与异常分支

| 起点 | 操作 | 成功结果 | 无法完成时 |
|---|---|---|---|
| 首页·发现 | 选择主机→输入电脑显示的 8 位码 | 验证设备身份、保存独立凭证，进入已连接首页 | 码错保留输入并给重试；证书变化只显示阻断与核验入口 |
| 首页·待处理 | 点待审批任务 | 打开审批弹窗，背景保留原页，关闭后仍能找到任务 | 请求失效/重复时弹窗禁用决定按钮并刷新来源状态 |
| 首页·新任务 | 选 Agent、工作区并输入目标 | 创建原生会话后进入会话页 | 主机离线或 Agent 不可用时不显示假成功，会话草稿不丢 |
| 会话管理 | 搜索、状态筛选、点会话 | 保持筛选上下文进入原会话 | 离线显示上次同步快照；刷新失败不清列表 |
| 会话 | 发送/停止/展开工具 | 发送状态从待发送→已送达→执行中；停止只作用当前轮次 | 失败保留内容可重试；上滑阅读不被流式输出拉到底 |
| 任务中心 | 切消息/下载、点任务 | 消息回对应会话；下载打开本机文件 | 文件丢失显示重新下载，不伪装可打开 |
| 文件 | 进入目录、预览、下载或长按管理 | 按 `FileKind` 能力内置预览/系统打开/保存 | 删除二次确认；预览不支持时说明并提供真实可用去向 |
| 协同 | 选 2 位以上可用 Agent、设置角色、派发同一指令 | 分别展示每位 Agent 的接受/运行/完成状态和结果 | 一位失败不拖垮其余；能力不支持的 Agent 不可选 |

### 审批弹窗状态机

`收到请求 → 待决定 → 提交中 → 服务端确认 → 已允许 / 已拒绝`。弹窗只放必要信息：Agent 与会话、操作目的、工作区、操作类型、原始命令和“拒绝 / 仅本次允许”两个明确按钮。提交中禁重复点击但仍可查看上下文；只有服务端确认后，首页、会话与任务中心才同步移除待处理。若超时、离线或服务端拒绝，保留请求和决定界面，展示原因与重试，不把关闭弹窗当作拒绝。多请求按到达顺序显示数量，不自动替用户决定。普通会话卡只显示入口，不承载审批动作。

### 侧边栏与回退

侧边栏的展开和收起是同一导航：顺序、图标、当前页高亮、任务角标完全相同；收起时每个图标都保留无障碍名称与点击区，折叠偏好持久化。左缘右滑跟手展开，松手按进度吸附；遮罩点击或返回原路收回。选择页面先收抽屉再导航，新的页面不带抽屉状态。主页面可以直接切换；来自某页的二级页返回该来源页。会话列表的搜索和筛选属于临时视图状态，返回先清临时状态；文件路径先退父目录；审批始终是最高优先级。页面、抽屉、弹窗各按进入路径反向退出，不出现“从左进、向下退”的跳跃。

## 原型交互与验收

打开 `prototype.html` 可切换页面；首页可从发现主机完成模拟配对；侧边栏可展开/折叠并进入页面；会话可搜索/筛选、进入聊天；聊天可输入、停止、查看工具详情；首页、任务中心或聊天可以打开同一个审批弹窗；批准/拒绝会同步清除待处理状态；文件可进入目录/预览；协同可选参与者后模拟派发；浏览器返回与页面返回均按上述优先级。原型只模拟界面，不执行真实 RPC，也不更改手机 App 数据。

验收以三件事为准：12 张图片在同一宽度和令牌体系内无溢出；主要交互能完成且回退不误触审批；设计信息与仓库 `README.md`、`ui/` 当前能力边界相符。实现落地建议先抽出状态栏/主机胶囊/状态徽章/审批弹窗四类共享组件，再逐页迁移；不要把展示用的样例状态写进生产逻辑。
