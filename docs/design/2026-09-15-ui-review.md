# PocketAgent UI 设计评审与优化方案

- 日期：2026-09-15
- 评审人：UI Designer
- 素材：真机截图 21 张（`docs/verify/evidence/2026-09-15/v1~v21*.png`，小米 13 / Android 16 / 深色主题）+ 全量代码扫描（`ui/` 23 个 Kotlin 文件）+ 既有设计规范《2026-09-15-pocketagent-ui-design-spec.md》的 WCAG 审计
- 范围：主页、侧边栏、会话列表（活跃/已归档/电脑）、聊天页、上下文窗口、任务中心、设置页

---

## 1. 总评

本轮 P2 重设计后，整体设计质量明显上升：设计令牌体系（Pa 色阶 Bg→Card→CardHigh→Hover 表达层级）、lucide 图标统一、卡片化布局、深色主题完成度高、动效（按压缩放/触感）一致性好。**视觉语言已经立住了。**

当前的主要短板不在"好看"，而在三件事：

1. **无障碍红线未守住** —— 低对比色配超小字的组合大量存在（实测数据见 §3）；
2. **手势的可预期性** —— 两处手势行为与用户直觉相悖（面板误关、快滑失效）；
3. **信息密度与状态可见性** —— 主页/会话列表缺少"正在运行"这一最关键状态的表达。

---

## 2. 数据证据（代码全量扫描）

| 指标 | 实测值 | 评注 |
|---|---|---|
| ≤11sp 小字号使用 | **84 处**（10.5sp×30、11sp×31、10sp×18、9.5sp×3、9sp×1） | 中文正文可读性底线建议 12sp，说明文字不低于 11sp |
| `Pa.TextTertiary`（#9E9EA6）直接用于 ≤11sp 小字 | **31 处**（11sp×12、10.5sp×11、10sp×6、9.5sp×2） | 对比度 2.7:1，WCAG AA 文本标准 4.5:1，**全部不达标** |
| `RoundedCornerShape` 取值 | **15 种**（14×30、50×25、12×19、16×9、18×7、10×5、8×5、20×5、22×4、13×3、11×2、2×2、17、26、15） | 圆角令牌失控，14/50/12 是事实主流，长尾应收敛 |
| 设置页分段文案 | 动态（`agentDisplay(runningAgent)`）| ✅ 无问题（排除疑点） |

既有设计规范已测得（浅色主题）：TextSecondary 5.4:1 ✅、Red 4.3:1 ⚠️临界、Accent 3.9:1 ❌（仅大字达标）、Green 3.1:1 ❌、**TextTertiary 2.7:1 ❌**。规范给出的 `AccentText/GreenText/RedText` 变体已落地，但 **TextTertiary 的达标变体未落地**，31 处违规就是证据。

## 3. 问题清单与优化方案

### P0 · 无障碍/可用性红线

**A1 · 低对比小字（31 处违规）**
- 现状：`TextTertiary #9E9EA6`（2.7:1）+ 10~11sp 的组合遍布全部页面：会话卡"N 条消息"、任务中心状态行、抽屉分组标签、设置页说明、主页副文字。
- 方案（三选一，推荐 ①）：
  1. **直接加深 TextTertiary 色值**：浅色 `#9E9EA6 → #767680`（≈4.6:1 达标），深色同步 `#77777F → #8E8E96`（深色背景上 4.5:1+）。**零调用点改动，一次生效**。视觉层级损失可接受——Tertiary 本就只承载"可忽略的辅助信息"。
  2. 新增 `Pa.TextTertiaryText` 逐点替换（31 处）——精确但琐碎。
  3. 全部升为 TextSecondary——层级感损失最大，不推荐。
- 同时设字号底线：**9/9.5/10sp 全部提到 11sp**（22 处），涉及"轮次徽标、日期、路径行"等。

**A2 · 会话行内重命名在 TalkBack 下无动作播报**（既有规范遗留项）
- `SwipeRevealRow` 已有 `customActions`，但行内 `OutlinedTextField` 无 `contentDescription` 语义标签。补 `Modifier.semantics { contentDescription = "重命名会话" }`。

### P1 · 高频体验损伤

**B1 · 抽屉面板空白处点击会误关抽屉**
- 现状（v3 验证实测）：点品牌头右侧空白，抽屉关闭。根因：遮罩 `pressable{requestClose()}` 挂在全屏根 Box 上，面板未消费的点击穿透到遮罩。用户预期"点在面板上=不关闭"。
- 方案：`DrawerPanel` 根 Column 加空点击消费：
  ```kotlin
  .clickable(interactionSource = remember { MutableInteractionSource() },
             indication = null) { }   // 吃掉面板内空白点击，阻止穿透遮罩
  ```

**B2 · 边缘右滑"快滑"不触发**
- 现状（实测）：280ms/500px 快滑无效，600ms 慢滑才唤出。真实用户边缘右滑常是快滑。
- 根因：快滑前段被 HyperOS 系统返回手势抢占（x<24dp 区域），起手 24~64dp 区间快滑时系统先行判定。
- 方案：a) `edgeSwipeToOpenDrawer` 增加 velocity 容忍——起手点 ≤64dp 时即使后续事件被抢，也在 `onDragCancel` 里按"已滑距离>40dp"兜底触发；b) 或接受现状，记录为已知限制。建议 a，改动约 6 行。

**B3 · 主页"最近任务"卡缺状态与准确性**
- 现状（v1 截图 + 代码）：① 无运行中指示（agent 正在跑的会话在主页看不出来）；② agent 图标硬编码 `R.drawable.agent_codex`（HomeScreen.kt:354）——未来多 agent 下全部显示 Codex；③ 无时间。
- 方案：标题行左侧加 5dp 状态点（`TurnSession.state(t.id).running` → Accent 呼吸动画，复用会话列表的状态点样式）；图标改从 thread 的 agent 字段解析（无字段则先保持现状并记 TODO）；副文字加"· HH:mm"。

**B4 · 聊天输入栏一行 6 元素**
- 现状（v12 截图）：`+`、回形针、"按需询问"胶囊、"上下文 272k"胶囊、模型名、发送键挤满一行，小米 13 上已无余量，小屏/大字号下必挤爆或误触。
- 方案（两步走）：
  1. 立即：模型名并入"上下文"胶囊左侧区域或收进模型卡入口（点击行为已存在）；保留主行 = 输入框 + 发送键 + 一个"加号"。
  2. 迭代："+"点开附件/按需询问面板，主行只剩 3 元素。

**B5 · 会话列表"分段"概念混杂**
- 现状（v5 截图）：`活跃 / 已归档 / 电脑` 三分段中，"电脑"是**来源**维度，前两个是**归档状态**维度；且连接卡+分段+列表同屏时首屏仅见 2 条会话，浏览效率低。
- 方案：分段改两组——`活跃 / 已归档` 为主分段，"电脑上的 codex 会话"降为列表顶部一张可折叠入口卡（显示数量徽标，点开进入专用列表）。首屏可多显示约 2 条。

### P2 · 打磨项

**C1 · 圆角令牌收敛**：15 种 → 5 档：`Card=16`、`Sheet=26`、`Chip/胶囊=50`、`Inner=12`、`Small=8`。在 `Pa` 中定义 `Pa.Radius*`，机械替换。

**C2 · 任务中心"待处理"命名不准**：统计的是 FAILED+INTERRUPTED，"待处理"暗示队列语义。改"**需关注**"（红点色不变）；"全部"数字与 tab 数量口径一致性检查。

**C3 · 抽屉缺任务中心选中态**：从任务中心页开抽屉（v4 实测），导航组无任何高亮。方案：`entries` 增加第 5 项"任务中心"（tab=4），与磁贴并存；或磁贴在 `currentTab==4` 时加选中描边。推荐前者——磁贴是"快捷"，导航项是"所在"。

**C4 · 主页 agent 网格"开发中"磁贴占半屏**（v1 截图 6 个灰态磁贴）。方案：可用 agent 保持 4 列网格；不可用的折叠为一行"更多 agent（开发中）›"入口，点开 ManageAgentsSheet。主页聚焦可用的东西。

**C5 · 上下文窗口读数动线**（v13 截图）：大数字"— / 272K tokens"在左、"0.0%"胶囊在右，视线往返。方案：百分并入主数字同一行（`3.2% · 8.7K / 272K`），胶囊只保留"剩余"一个。

**C6 · 主页右上白色竖条**（v1/v5/v12 可见）：疑似某滚动指示器默认样式，与深色主题不符。查明来源（LazyVerticalGrid 自定义指示器或调试残留），隐藏或按 `Pa.Hover` 重新着色。

**C7 · back 键行为**：会话列表 back 直接退桌面符合 Android 惯例，不算缺陷；可选优化为 `moveTaskToBack`（退后台不杀进程，重开更快）。仅记录，不强求。

## 4. 优先级矩阵（影响 × 成本）

```
 影响大 │  A1 色值加深      B1 面板透点   B4 输入栏分层(2步)
        │  (1处改全局)      (3行)        B3 主页状态点
        │  B5 分段重构
        │
 影响小 │  C2 改名          B2 快滑兜底   C1 圆角收敛(机械)
        │  C5 读数合并      C3 选中态     C4 网格折叠
        │                                C6 滚动条
        └─────────────────────────────────────
             成本低              成本高
```

**建议实施顺序**：A1（一次改色全局达标）→ B1（3 行防误关）→ B3/C2/C5/C3（小改快赢）→ B4/C1（下一迭代）→ B5/C4（结构调整，单独排期）。

## 5. 附：值得保留的优点（避免过度修正）

- 色阶表达层级（无投影扁平风）执行得很纯粹，不要引入阴影破坏它；
- 按压 spring 回弹 + 触感反馈的"手感"是差异化亮点，所有新组件必须继承 `pressable`；
- 撤销条（UndoBar）"计时结束才提交"的软删除语义是对的，别改成确认弹窗；
- 上下文窗口"本轮/累计"双口径与"构成估算"是超越同类遥控器的信息设计，保留；
- 设置页三分段（全局/当前 Agent/其他）信息架构正确，文案已动态跟随 agent。
